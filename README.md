# ◆ SwagCod

**Десктопный код-агент: Rust-ядро, Tauri v2, Svelte 5. Всё локально, всё твоё.**

Модель читает, пишет и запускает код по твоей задаче: инструменты с подтверждениями,
MCP-серверы, JS-плагины, суб-агенты, семантический поиск, фоновые задачи,
персистентная память в трёх областях, уведомления, loopback REST API и дашборд
телеметрии — в нативном окне с холодным стартом **40 мс**.

## Что умеет

| | |
|---|---|
| 💬 **Живой стрим** | Инкрементальный markdown с подсветкой, reasoning-поток, курсор стрима, токены и ток/с, очередь реплик, стоп-кнопка |
| 🧠 **Живые мысли** | Reasoning стримится в транскрипт токенами прямо во время хода, а не появляется целиком в конце: режим «живые» или «все» (включая завершённые). Мысли принимаются из `reasoning_content`, `reasoning` или `thinking` — шлюзы кладут их в разные поля |
| 🗂 **Память** | Три области: глобальные факты (вшиваются в промпт каждого хода), заметки сессии, факты рабочей папки. Запись многострочная (кап 4000), импорт и экспорт txt/md, селектор сессии — править память можно любой сессии, не переключая активный чат |
| 🔔 **Уведомления** | Звук и toast: ход завершён, ошибка, запрос подтверждения. Звук синтезируется встроенно, внешних файлов нет; без аудиоустройства (headless, RDP без звука) звук молча пропускается, а уведомление работает |
| ♻️ **Hot-reload** | MCP-серверы, JS-плагины и скиллы перечитываются без перезапуска приложения — правка файла или новая запись в реестре подхватываются по кнопке |
| 📁 **Правила папки** | Набор на рабочую папку и её подпапки: allow/deny команд, отключение MCP/плагинов/скиллов, `system_prompt_append`, свой TTL сессий, исключение из очистки. Плюс авто-очистка: фоновый воркер сносит старые сессии по TTL |
| 🎛 **Модель по сессиям** | Каждая сессия помнит свою модель и не переключает глобальную; тумблер в настройках, сброс на глобальную одной кнопкой |
| 🔀 **Провайдеры** | 12 пресетов (OpenAI, Anthropic, Kimi, DeepSeek, OpenRouter, Zen, Gemini, Groq, Mistral, xAI, Ollama, LM Studio) + custom со своим endpoint; нативный клиент Anthropic `/v1/messages`; ключи под DPAPI, наружу только `has_key`; Fetch models с превью и явным сохранением |
| 🛠 **Инструменты** | Файлы (read/write/patch), поиск (grep/glob), bash через шелл с таймаутом и убийством дерева, fetch_url, web_search — всё с журналированием и подтверждениями |
| 🔌 **MCP** | Внешние инструменты по Model Context Protocol (stdio): реестр серверов, статусы, общий список тулов с встроенными |
| 🧩 **JS-плагины** | `plugins/*.js` в изолированном vm-контексте sidecar'а: дедлайн, read-only prefs, `swagcod.define({name, handler})` |
| 🤖 **Суб-агенты** | Инструмент `subagent` — изолированная ветка хода: только безопасные тулы, своя дешёвая модель (аргумент `model`), бюджет токенов и раундов, отчёт родителю, дерево ходов в UI |
| 🔎 **Семантический поиск** | Embeddings-индекс воркспейса (облако или локальный лексический фолбэк), кэш в отдельной базе, периодическая переиндексация |
| 📚 **Поиск по истории** | FTS5-индекс всех сообщений (текст и reasoning) во всех сессиях: `/search` в палитре, сниппет с подсветкой совпадений, находка открывает свою сессию. Префиксный и регистронезависимый; слова должны встретиться внутри одного сообщения; пустой запрос — ошибка, а не «нашлось всё» |
| 📋 **Фоновые задачи** | Очередь в SQLite, воркер с экспоненциальным backoff (30 с → 30 мин, до 5 попыток), периодические задачи, восстановление сирот после краша |
| 💾 **Копия базы** | ревизия 65: при запуске, если сутки прошли, SQLite снимает `VACUUM INTO` в `<каталог базы>/backups/swagcod-backup-<время>.db`; хранятся 7 последних. История сессий — единственное, что нельзя восстановить из репозитория |
| 🌐 **HTTP API** | Loopback REST + SSE рядом с шиной: те же команды, что IPC. Bearer-токен под DPAPI, по умолчанию выключен |
| 📈 **Телеметрия** | Таблица `metrics`, сэмпл раз в минуту, латентность провайдера на первый токен стрима; дашборд: токены/день, латентность, лаги шины |
| 📥 **Импорт из DSH** | Перенос истории DSH Desktop (`session.v3.jsonl.zstd`) — идемпотентно, отдельным соединением, догрузка оборванных сессий, конфиги MCP/плагинов; запуск кнопкой в настройках |
| 🖥 **Терминал** | Настоящий PTY с ANSI-парсером и кольцевым буфером |
| 🔐 **Безопасность** | API-ключ под DPAPI Windows, политики подтверждений (глобальная + per-session), журнал одобрений, песочница путей fsx: относительные пути не выходят за cwd (в т.ч. у grep/glob), абсолютный и якорный путь (`C:x`, `\x`, `\\srv`, `/x`) вне рабочей папки при `on_dangerous` уходит на подтверждение человека, в суб-агенте — честный отказ; write в DOS-устройства (`nul`/`con`) — отказ |
| 🎨 **Внешность** | 4 темы, студия (свой акцент, тонировка, медиафон gif/mp4/webm), масштаб окна 60–200%, свои штриховые SVG-иконки — эмодзи в UI нет |

**Горячие клавиши:** ⌘K ввод · ⌘P палитра команд · ⌘F поиск · ⌘M модель · ⌘B панель · ⌘±/0 масштаб

Три вещи в ревизиях 51–59 имеют неочевидную семантику — их стоит знать:

**Факт папки не наследуется в подпапки.** Правила папки резолвятся от листа к
корню (унаследованный запрет защищает), а факты памяти принадлежат ровно той
папке, где сохранены: унаследованный факт молча менял бы поведение модели там,
где он не действует. Совпадение пути побайтовое по `cwd` хода — один и тот же
каталог, открытый по разным путям, даст две разные области.

**Длинный промпт живёт в файле, а не в памяти.** Кап строки памяти — 4000
символов (столько же, сколько секция фактов в промпте), поэтому импортированный
промпт помещается целиком. Текст длиннее — это `.swagcod/rules.md` папки, у него
кап 8000: он и создан для промпта на весь проект.

**Поднятие версии обязано нести `Cargo.lock`.** `Release` гоняет
`cargo test --locked`, и рассинхрон роняет шаг до всякой сборки. Автообновление
сравнивает версии по semver, поэтому переопубликовать тот же номер бессмысленно —
доставка не сработает.

| Крейт | Зона | Принцип |
|---|---|---|
| `swagcod-core` | шина событий, сессии, машина хода, контракт Store | **без tauri и без async-рантайма** — headless-тесты и бенчи |
| `swagcod-provider` | OpenAI-совместимый клиент, SSE-парсер, fallback-цепочка B-6 | облако, агрегаторы, Ollama/llama.cpp одним кодом |
| `swagcod-pty` | PTY, ANSI, кольцевой буфер | |
| `swagcod-fsx` | файлы, watch, diff, песочница путей | |
| `swagcod-app` | Tauri-обёртка: окна, IPC, воркеры, HTTP API | тонкий слой над ядром |

Хранилище — better-sqlite3 в Node-sidecar'е (как просил пользователь), аварийный
фолбэк — встроенный rusqlite; контракт `Store` один на оба бэкенда, паритет
покрыт тестами.

## HTTP API (E-7)

По умолчанию **выключен**. Включи портом и перезапусти: `SWAGCOD_HTTP_PORT=47479`
(или prefs-ключ `http_api_port`). Токен (32 байта CSPRNG, хранение под DPAPI)
показывается в Настройки → Безопасность. Слушает только `127.0.0.1`.

| Метод | Маршрут | Что делает |
|---|---|---|
| GET | `/health` | liveness без токена |
| GET | `/v1/diagnostics` | шина, лаги, активные ходы, uptime |
| GET | `/v1/sessions` | список сессий (`SessionBrief[]`) |
| GET | `/v1/models` | каталог моделей активного провайдера (F-9) |
| POST | `/v1/sessions` | `{cwd, model?}` → `SessionBrief` (F-9) |
| POST | `/v1/sessions/transcript` | `{session_id}` → лента сессии в wire-формате B-8 (F-9) |
| POST | `/v1/turns` | `{session_id, message, model?, temperature?}` → `{turn_id}` |
| POST | `/v1/turns/stop` | `{session_id}` → остановка живого хода (F-9) |
| POST | `/v1/turns/revert` | `{session_id, turn_id}` → откат к снимку хода: git-объект в репозитории, теневая копия дерева вне его (F-5, rev64) |
| POST | `/v1/checkpoints` | `{session_id}` → какие ходы можно откатить (F-5) |
| POST | `/v1/approvals` | `{call_id, decision: approved\|denied}` |
| GET | `/v1/events` | SSE-поток всех событий шины |

Все маршруты, кроме `/health`, требуют `Authorization: Bearer <токен>`.
POST-маршруты — только с JSON-телом: query-строка в парсере отбрасывается
(`parse_head`), поэтому даже «чтение» (`/v1/checkpoints`,
`/v1/sessions/transcript`) сделано POST-ом. Ошибки — честные 400/401/404 с
`{"error":"…"}`; SSE не рвётся на лаге broadcast, а шлёт комментарий
`: lagged N`.

```bash
TOKEN=...   # Настройки → Безопасность → «Копировать токен»
curl -s http://127.0.0.1:47479/v1/diagnostics -H "Authorization: Bearer $TOKEN"
curl -s http://127.0.0.1:47479/v1/turns -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"session_id":"s-1","message":"почини тесты"}'
curl -sN http://127.0.0.1:47479/v1/events -H "Authorization: Bearer $TOKEN"
```

## SwagCod Phone (F-9)

Телефонный клиент — отдельный проект `dsh-phone` (PWA + python-гейтвей на
stdlib, живёт вне этого репозитория). Он подключается к HTTP API SwagCod
адаптером `swagcod_backend.py`: тот же интерфейс бэкенда, что у моста DSH,
поэтому ни HTTP-роутинг гейтвея, ни его long-poll, ни черновики не меняются.
Адаптер переводит RPC-методы телефона в маршруты API и события шины (SSE) — в
события гейтвея, так что телефон получает живой стрим, а не опрос.

Подключение: включить API на `47479`, скопировать токен из Настройки →
Безопасность в `swagcodToken` конфига гейтвея, выставить `"backend":
"swagcod"` и запустить `python gateway.py`. Полное описание, таблица
«метод телефона → маршрут API», каноническая копия адаптера с его 34 тестами и
два скрипта ручной проверки — в [`tools/phone/README.md`](tools/phone/README.md).

```powershell
# сторона SwagCod: 15 проверок API (с -Turn ещё и настоящий ход)
powershell -NoProfile -ExecutionPolicy Bypass -File tools\phone-check.ps1 -Token <hex>
# вся цепочка через гейтвей: 17 проверок, а с --create — 24 (новый чат, ход, стрим)
python tools\phone\phone-gateway-check.py --config <путь>\dsh-phone\config.json --create <папка> --model <id>
```

Чего телефон против SwagCod не умеет: вложения (API принимает только текст),
смена политики подтверждений (намеренно: телефон не должен расширять себе
права удалённо), откат хода (маршрут есть, UI в телефоне нет). Честный список
отдаёт `runtime.getCapabilities`.

## Быстрый старт

Нужны: Rust stable (MSVC), Node 20+, pnpm 11+.

```powershell
cp .env.example .env      # заполни SWAGCOD_API_KEY
pnpm install              # зависимости фронтенда
pnpm --filter swagcod-desktop build          # фронтенд в dist/
cargo build --release -p swagcod-app --features tauri/custom-protocol
# результат: target/release/swagcod-app.exe
```

> ⚠️ Без `--features tauri/custom-protocol` бинарник будет искать localhost:5173
> и покажет ERR_CONNECTION_REFUSED — грабля Tauri v2 (DECISIONS.md §7).

```powershell
cargo test --workspace                       # 790 Rust-теста (1 ignored)
pnpm --filter swagcod-desktop test           # 199 TS-тестов
cargo clippy --workspace --all-targets -- -D warnings
# F-11: сквозная проверка хода без сети и ключей — эхо вместо провайдера
cargo test --release -p swagcod-app --test e2e_smoke
# ревизия 84: зондаж sidecar-стора мусорными запросами (находок нет)
node tools/probe-store-sidecar.js
```

## Установка и обновление

**Просто поставить:** скачай `SwagCod-setup.exe` из
[Releases](https://github.com/Swwag666/SwagCode/releases) и запусти —
установка под текущего пользователя (без админа), ярлык в меню Пуск,
WebView2 докачается сам, node-рантайм и sidecar уже внутри установщика.
Текущий релиз — **v0.3.0**.

**Автообновление:** приложение читает манифест `latest.json` из GitHub
Releases (`releases/latest/download/latest.json`), сверяет версию и
подпись minisign, качает новый setup и ставит его. Ручной запуск:
Настройки → General → «Обновления» → «Проверить»; прогресс загрузки
честный, в конце — «Перезапустить сейчас». Неподписанный или чужой
манифест отвергается: подпись обязательна.

**Сборка релиза (для сопровождающих):**

```powershell
# ключ подписи — один раз (генерится в профиль пользователя, вне репы):
npx tauri signer generate -w $env:USERPROFILE\.swagcod-updater\swagcod-updater.key
# релиз локально: setup.exe + .sig + SwagCod.exe + latest.json в releases/
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build-release.ps1 -Sign -Latest
# подпись артефакта против публичного ключа из tauri.conf.json:
python tools\verify-updater-signature.py releases\SwagCod-setup.exe releases\SwagCod-setup.exe.sig
```

Или CI: запушь тег `vX.Y.Z` — workflow `Release` (tauri-action) сам
соберёт NSIS, подпишет артефакты и опубликует релиз с `latest.json`.
Нужны секреты репозитория `TAURI_SIGNING_PRIVATE_KEY` и
`TAURI_SIGNING_PRIVATE_KEY_PASSWORD` (содержимое
`~/.swagcod-updater/swagcod-updater.key` и `password.txt`); выставлены.

Релиз ломается тихо, поэтому перед тегом проверь три вещи:

1. **Версия поднята** в `Cargo.toml` и `crates/app/tauri.conf.json`, и
   **`Cargo.lock` лежит в том же коммите**: `Release` гоняет
   `cargo test --locked`, и рассинхрон роняет шаг до всякой сборки. Тот же
   номер повторно публиковать бессмысленно — апдейтер сравнит semver и
   скажет «обновлений нет».
2. **Секреты подписи на месте** (`gh secret list`). Без них ворота пройдут
   зелёными, а `tauri-action` умрёт: `createUpdaterArtifacts: true` требует
   подписи.
3. **Подпись проверена.** `tools/verify-updater-signature.py` сверяет
   `key_id`, подпись содержимого (Ed25519 над Blake2b-512 prehash) и
   глобальную подпись trusted comment. У `tauri-cli` команды `verify` нет, а
   неверная подпись означает, что обновление не получит никто, причём сборка
   и публикация выглядят при этом зелёными. Режим `--tag vX.Y.Z` проверяет
   уже опубликованный релиз, а не только локальный файл.

> ⚠️ Проверка обновлений идёт анонимным запросом к
> `releases/latest/download/...`, поэтому и репозиторий, и релизы должны быть
> публичными, а релиз — не черновиком: у черновика этот адрес не резолвится, и
> приложение честно покажет ошибку сети вместо «обновлений нет».

## Конфигурация

Ключ провайдера живёт в `.env` (в `.gitignore`) или под DPAPI Windows
(команда «Зашифровать» в Настройки → Безопасность; приоритет: `.env` → DPAPI).

| Переменная | Смысл |
|---|---|
| `SWAGCOD_API_KEY` · `SWAGCOD_BASE_URL` · `SWAGCOD_MODEL` | провайдер (base по умолчанию `https://rustvy.xyz/v1`) |
| `SWAGCOD_FALLBACKS` | B-6: цепочка резервных точек `url\|key\|model;…` (пустой key = локальный эндпоинт) |
| `SWAGCOD_SUMMARIZER_MODEL` | B-3: модель свёртки контекста (пусто = модель сессии) |
| `SWAGCOD_STORE` · `SWAGCOD_NODE` · `SWAGCOD_STORE_SIDECAR` | авто/node/sqlite-бэкенд хранилища |
| `SWAGCOD_EMBEDDINGS_MODEL` · `SWAGCOD_EMBEDDINGS_MODE` · `SWAGCOD_SEMANTIC_DB` | E-2: семантический поиск |
| `SWAGCOD_MCP_TIMEOUT_MS` | E-3: таймаут инструмента MCP (дефолт 60000) |
| `SWAGCOD_PLUGINS_DIR` · `SWAGCOD_JS_TIMEOUT_MS` | E-4: каталог и дедлайн JS-плагинов |
| `SWAGCOD_TASKS_POLL_MS` | E-5: период воркера задач (дефолт 15000) |
| `SWAGCOD_SUBAGENT_MAX_ROUNDS` · `SWAGCOD_SUBAGENT_BUDGET_TOKENS` | E-6: лимиты ветки суб-агента |
| `SWAGCOD_TURN_MAX_ROUNDS` · `SWAGCOD_TURN_BUDGET_TOKENS` | ревизия 62: лимиты главного хода (40 раундов, 2 млн токенов) — останавливают ход, который крутит инструменты без конца; сделанное остаётся в истории |
| `SWAGCOD_SHADOW_DIR` | ревизия 64: каталог теневых снимков (по умолчанию `~/.swagcod/shadow`) — откат хода в папке без git; каталоги сборки и файлы больше 2 МБ в снимок не входят, снимки старше 30 дней выметаются |
| `SWAGCOD_HTTP_PORT` | E-7: порт loopback REST API (не задан — выключен) |
| `SWAGCOD_APPEARANCE` · `SWAGCOD_BG_MODE` | оверрайды темы и фона при старте |
| `SWAGCOD_ECHO_PROVIDER` | F-11: вместо боевого провайдера — встроенное эхо (ответ = «эхо: <сообщение>», счёт токенов честный). Сети и ключа не требует, в журнале провайдер виден как `echo`. Для сквозных проверок и CI; `0`/`false`/`off`/пусто — выключено |

Полный шаблон с комментариями — [`.env.example`](.env.example).
