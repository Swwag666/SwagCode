# CLUSTER — локальный кластер VoidSearchSwag

Три полных инстанса на одной машине: у каждого свой tor-демон, база и пул.
Никаких трёх хостингов: модель - реплики с gossip-синком, а не шардинг
(шардингу нужен консенсус, для одной машины это оверкилл).

## Запуск

```bash
# один раз: tor+база+chromium в каждую дату
VOIDSEARCH_DATA_DIR=./node1 ./voidsearchswag setup
VOIDSEARCH_DATA_DIR=./node2 ./voidsearchswag setup
VOIDSEARCH_DATA_DIR=./node3 ./voidsearchswag setup

# пуск
sh docs/cluster-local.sh        # linux/macOS
docs\cluster-local.bat          # windows
```

Готовые скрипты лежат в `docs/`: поменяй `CHANGE_ME` на свой токен.
Токен обязан быть одинаковым на всех нодах: пиры ходят друг к другу
с тем же Bearer, что и агенты.

## Как устроен синк

- `GET /peer/export?limit=&status=` - выгрузка пула и охот ноды.
  Без серверного токена всегда 403, с чужим - 401. Пул наружу без
  auth не отдаётся никогда.
- `peer_sync` - забрать выгрузки всех пиров и смержить: onion по url
  (Upsert), охоты по паре query+mode (дубликат пропускается).
- `peer_list` - живость пиров: latency `/health` каждого.
- Фон: каждый час синк со всеми пирами (`peerSyncTick`), мёртвый пир -
  запись в лог, остальные синкаются.

## Семантика (честно)

- Реплики, не шарды: каждая нода бегает все свои охоты. Охоты синкаются
  как определения (запрос+режим+расписание), находки у каждой свои -
  дедуп находок между нодами делает агент по `hunt_id + hash`.
- Конфликты статусов адресов: побеждает последний увидевший (Upsert
  перезаписывает). Для пула живости это нормально: свежее наблюдение
  точнее старого.
- Падение ноды: агент переподключается к следующей (healthcheck
  `/health`), пул и охоты уже продублированы синком. Потеря - только
  находки с момента последнего синка.
- Пиры задаются `VOIDSEARCH_PEERS` через запятую. Пустой список -
  одиночный сервер, `peer_sync` вернёт ошибку текстом, а не падением.
